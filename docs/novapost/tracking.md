# Нова пошта API: відстеження відправлень

Джерело: розділ «Трекінг» → `TrackingDocumentGeneral.getStatusDocuments` на https://developers.novaposhta.ua/.
У проєкті відстеження **ще не реалізовано**; це довідка для ідеї «статуси посилки в Telegram».

## Запит
```json
{ "apiKey": "…", "modelName": "TrackingDocumentGeneral", "calledMethod": "getStatusDocuments",
  "methodProperties": { "Documents": [ { "DocumentNumber": "20400048799000", "Phone": "380600000000" } ] } }
```
- До **100 накладних за один запит**. `Phone` (одержувача чи відправника) дає розширену інформацію; з ключем API повертаються коректні дані відправника й одержувача, без ключа — обмежені.
- HTTP 200 завжди, перевіряти `success`.

## Коди статусів (`StatusCode`)
| Код | Значення |
|---|---|
| 1 | Відправник створив накладну, але ще не надав до відправки |
| 2 | Видалено |
| 3 | Номер не знайдено |
| 4, 41 | Відправлення в місті відправника (міжобласне / локальне) |
| 5 | Відправлення прямує до міста одержувача |
| 6 | У місті одержувача, орієнтовна доставка до відділення |
| 7 | Прибув на відділення |
| 8 | Прибув на відділення (завантажено в поштомат) |
| 9 | Відправлення отримано |
| 10 | Отримано; грошовий переказ видадуть у касі |
| 11 | Отримано; грошовий переказ видано одержувачу |
| 12 | Нова пошта комплектує відправлення |
| 15 | Вже в дорозі до України |
| 101 | На шляху до одержувача |
| 102, 103 | Відмова від отримання (102: створено замовлення на повернення) |
| 104 | Змінено адресу |
| 105 | Припинено зберігання |
| 106 | Одержано і створено ЕН зворотної доставки |
| 107 | Переміщено з PUDO до основного відділення |
| 111 | Невдала спроба доставки (немає одержувача або зв'язку) |
| 112 | Дата доставки перенесена одержувачем |
| 124 | Знищено внаслідок ворожої атаки |

## Корисні поля відповіді
`Number`, `StatusCode`, `Status`, `ScheduledDeliveryDate`, `ActualDeliveryDate`, `DateFirstDayStorage`, `DaysStorageCargo`, `StoragePrice`, `AfterpaymentOnGoodsCost`, `AmountToPay`, `AmountPaid`, `DocumentCost`, `WarehouseRecipient`, `RecipientFullName`, `PossibilityCreateReturn`, `PossibilityCreateRefusal`.

## Ідеї для реалізації
- Раз на кілька хвилин збирати ТТН зі станом «не завершено» й питати їх пачками по 100.
- Сповіщати менеджера й клієнта на кодах 7/8 (прибуло), 9/10/11 (отримано), 102/103 (відмова), 111 (невдала спроба), 105 (припинено зберігання).
